## プロジェクト概要

**Q-Quest 量子神託** は、QUBO（Quadratic Unconstrained Binary Optimization）の考え方を用いて、  
日本文化における「縁」や「中今」の感覚を、現代的な体験として再構成するプロジェクトです。

一見すると「キャラクター神託」や「おみくじ」のように見えますが、  
内部では、ユーザーの状態を数理的なベクトルと相性構造へ変換し、  
**今の自分に最も調和する1柱** を選ぶ仕組みになっています。

現行プロトタイプでは、ユーザーが入力した悩みや願いから、  
関連する **格言・仏典の言葉** を複数選定し、  
それらを絡めて、悩みに応答する神託文を生成します。

## 現行実装の範囲

現行版の中核は、以下の最小実証です。

1. 悩み・願いの文章からキーワードを抽出する
2. 文章入力と3軸スライダーから、12次元の誓願必要度ベクトルを生成する
3. 12神×12誓願の相性行列 `W` を用いて、神ごとの適合度を計算する
4. 12神の中から1柱だけを選ぶ **one-hot制約付きQUBO** を構成する
5. シミュレーテッドアニーリング（SA）でサンプリングし、観測結果として神を提示する
6. 選ばれた神、上位誓願、入力キーワードをもとに、格言・仏典を後段ロジックで選定する
7. 神託文、キーワード球体、QR共有を表示する

重要な点として、**現行実装では「神」と「お告げ」を同時に選ぶ結合QUBOはまだ実装していません。**  
格言・仏典・神託文の選定は、神選択QUBOの後段で行うスコアリング処理です。

したがって、現行成果は次のように位置づけます。

```text
現行成果：
12神から1柱を選ぶ one-hot QUBO + 格言・仏典の後段スコアリング + 神託UI

将来拡張：
神 × お告げ × 格言 × 仏典 × 匿名ユーザー球体を同時に扱う多層QUBO
```

## アルゴリズム概要

### 1. 悩み文からキーワードを抽出

ユーザーが入力した悩みや願いの文章から、  
意味を持つ単語やフレーズを抽出します。

例：

```text
仕事で迷っていて、次の一歩が踏み出せない
```

このような入力から、

```text
仕事 / 迷い / 一歩 / 踏み出せない
```

のようなキーワードを取り出します。

### 2. 入力から誓願必要度ベクトルを生成

文章入力と3軸スライダーをもとに、  
12個の誓願それぞれに対する必要度を計算します。

```text
v = [v1, v2, ..., v12]
```

ここで `v(j)` は、  
「今、その誓願がどれだけ必要か」を表す値です。

### 3. 各神との相性を計算

各神が各誓願をどれだけ体現しているかを表す重み行列 `W` を使い、  
神ごとの適合度を計算します。

```text
score_i = Σ_j W(i,j) * v(j)
```

- `i` : 神の番号
- `j` : 誓願の番号
- `W(i,j)` : 神 `i` が誓願 `j` をどれだけ体現しているか
- `v(j)` : ユーザーにとって誓願 `j` がどれだけ必要か

### 4. QUBOとして定式化

12神の中から必ず1柱だけを選ぶため、  
one-hot制約付きQUBOとして定式化します。

```text
E(x) = Σ_i (-score_i) x_i + P(Σ_i x_i - 1)^2
```

- `x_i` : 神 `i` を選ぶなら1、選ばないなら0
- `score_i` : 神 `i` の適合度
- `P` : one-hot制約のペナルティ
- `Σ_i x_i = 1` : 必ず1柱だけ選ぶ制約

この現行QUBOは、12神選択をQUBO形式で表現した最小構成です。  
現規模では古典計算でも処理可能であり、量子アニーリングの優位性を主張する対象は、将来の多層・多人数拡張です。

### 5. シミュレーテッドアニーリングで観測

QUBOエネルギーを最小化するように、  
シミュレーテッドアニーリングで複数回サンプリングします。

最も調和する神、または観測頻度の高い神を、  
今回の神託結果として表示します。

現行プロトタイプでは、検証可能性を確保するため乱数シードを指定できます。  
そのため、現行実装は「真の非再現性」を実現するものではなく、再現可能なSA検証です。  
文化体験としての一回性をさらに高める場合は、将来拡張として量子乱数生成器（QRNG）などを別途検討します。

### 6. 格言・仏典を選定

ユーザーの悩み、抽出キーワード、上位誓願、選ばれた神の性格をもとに、  
Excel内の言葉データから複数の格言・仏典を選びます。

対象となる主なシート：

- `QUOTES`
- `Sheet2_FIXED`
- `仏典`
- `BUDDHIST_QUOTES`
- `DHAMMAPADA`

### 7. 複数の言葉を絡めて神託文を生成

選ばれた神、強く出た誓願、十二因縁の流れ、格言・仏典の言葉を組み合わせ、  
ユーザーの悩みに応答する神託文を生成します。

### 8. キーワード球体を可視化

入力文から抽出されたキーワードをもとに、  
関連する単語の関係を3D球体として可視化します。

これは、ユーザーの悩みがどのような意味の場に置かれているかを、  
視覚的に感じるための補助表現です。

## QUBOモデルの詳細

### 適合度

神 `i` の適合度は以下で計算します。

```text
score_i = Σ_j W(i,j) * v(j)
```

- `W(i,j)` : 神 `i` と誓願 `j` の相性
- `v(j)` : 現在のユーザーに必要な誓願 `j` の強さ

### エネルギー化

適合度が高いほど選ばれやすくするため、  
エネルギーは `-score_i` として扱います。

```text
linear_E_i = -score_i
```

### one-hot制約

12神の中から必ず1柱だけを選ぶために、  
以下のペナルティ項を加えます。

```text
P(Σ_i x_i - 1)^2
```

### 最終的なQUBO

```text
E(x) = Σ_i linear_E_i x_i + P(Σ_i x_i - 1)^2
```

ここで、

```text
linear_E_i = -score_i
```

です。

### 現行QUBOの位置づけ

このQUBOは、現行プロトタイプにおける12神選択の最小実装です。  
one-hot制約を明示的に扱うことで、将来的に以下のような制約や相互作用を追加できる構造を確保しています。

- 複数神の組合せ選定
- 誓願同士の相互作用
- 神とお告げの整合度項
- 身体データ・環境データによる補正
- 匿名ユーザー球体の近傍配置
- 過密回避・匿名性制約

ただし、現行の12神選択のみで量子優位性を主張するものではありません。  
量子アニーリングの有用性は、上記のような多層・多人数の組合せ最適化へ拡張した段階で検証する想定です。

## QUBOを使う理由

このアプリでは、単純なランキングに見える処理をQUBO形式へ変換することで、以下の拡張性を持たせています。

- one-hot制約を自然に扱える
- 将来的に複数神の組合せ選定へ拡張できる
- 誓願同士の相互作用を追加できる

## 格言・仏典選定の考え方

格言や仏典の言葉は、完全ランダムではなく、  
以下の要素をもとにスコアリングされます。

- 入力文に含まれるキーワード
- 上位誓願
- 選ばれた神
- 神の役割
- タグ情報
- 言葉の長さ
- 格言温度

格言温度を高くすると、多様な言葉が出やすくなります。  
低くすると、より適合度の高い言葉が選ばれやすくなります。

## キーワード球体と将来の共感コミュニティ

現行プロトタイプでは、ユーザーの悩み文から抽出されたキーワードをもとに、  
関連語を3D球体として可視化します。

将来的には、この球体表現を拡張し、匿名化・抽象化された複数利用者の悩み球体を、  
同じ意味空間上に配置する「量子絵馬」へ発展させます。

この構想では、直接メッセージ交換や個人特定を目的としません。  
近い悩みや願いを持つ人の存在を、近傍にある匿名球体として静かに示すことで、  
「一人で悩んでいるのではない」という感覚と、自己省察のきっかけを提供します。

プライバシー保護のため、将来実装では以下を前提とします。

- 氏名、連絡先、個人を特定できる情報を保存・表示しない
- 悩み本文をそのまま公開せず、抽象化したキーワードやベクトルとして扱う
- 他者との直接連絡機能を設けない
- 医療・法律・金融・宗教的判断を代替しない
- 不安定な心理状態の利用者が結果に過度に依存しないよう免責と相談導線を設ける

この多人数の匿名球体配置は、ユーザー数の増加とともに、クラスタリング、近傍配置、過密回避、匿名性制約を含む組合せ最適化問題へ発展します。  
ここが、将来的な量子アニーリング活用の主要な検証対象です。

## QR共有の注意点

### 正しい共有URL

```text
https://q-quest-twelve-vows.streamlit.app/?oracle=...
```

### 間違った共有URL

```text
http://localhost:8501?oracle=...
```

`localhost` は、そのPC自身を意味します。  
スマホから読み取ると、スマホ自身の `localhost` を探してしまうため、神託結果を表示できません。

そのため、QR共有では必ず Streamlit Cloud の公開URLを使用してください。
